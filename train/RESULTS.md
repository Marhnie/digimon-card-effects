# GPU 학습 결과 (중간)

환경: GTX 1660 SUPER (6GB), CUDA 드라이버 12.6, torch 2.6.0+cu124. roberta-large는 bs 4 × grad_accum 4(유효 배치 16)로 학습.
모델 선택은 valid의 (cov@95 + acc)로만 했고, 주 결과는 `test_with_valid_threshold`(valid 문턱을 test에 적용)예요.

## 네/아니요 판정

| 실험 | 상태 | test.acc_all | valid 문턱 @97 → test 커버리지 / 정확도 | valid 문턱 @98 → test 커버리지 / 정확도 | 엔진 단독 (≥0.80) | 엔진+모델 합집합 |
|---|---|---|---|---|---|---|
| (1) large k=5 | 완료 | 81.4% | 30.3% / 97.8% | 14.7% / 95.5% | 48.2% / 99.0% | 50.6% / 99.0% |
| (2) large k=0 (선례 없음) | 완료 | 78.6% | 25.0% / 96.0% | 23.5% / 95.7% | 48.2% / 99.0% | 52.3% / 98.1% |
| (3) base k=5 | 완료 | 74.0% | 2.2% / 100% (valid 문턱 0.979, 13문항 수준) | 2.2% / 100% (동일 문턱) | 48.2% / 99.0% | 48.9% / 99.0% |
| (4) large k=5 seed 1 | 완료 | 76.6% | 28.0% / 91.0% | 16.4% / 90.8% | 48.2% / 99.0% | 미측정 |
| (5) large k=5 seed 2 | 완료 | 76.7% | 34.8% / 98.1% | 33.8% / 98.5% | 48.2% / 99.0% | 미측정 |
| (6) large k=8 seed 13 | 완료 | 76.7% | 23.0% / 94.9% | 5.5% / 100% | 48.2% / 99.0% | 미측정 |

시드 반복(seed 13 / 1 / 2)의 @97 커버리지는 30.3%, 28.0%, 34.8%예요. 평균은 약 31%이고 정확도는 91~98%로 흔들려요. 그래서 k=5의 우위는 시드 차이 안에 있어요. k=8은 @97에서 23.0%로 k=5보다 낮아요.

base의 valid 95% 문턱(0.958)을 test에 적용하면 커버리지 18.9%, 정확도 92.0%예요. 결과 확인 전 가장 낮은 항목이에요.

test 기준 커버리지(test에서 직접 고른 문턱, 참고용·낙관적): (1) @95 44.2%, @97 40.9%, @99 12.4% / (2) @95 27.6%, @97 18.6%, @99 10.2%.

### 결론 (현재까지)
- 선례는 97% 목표에서 도움이 되는 것으로 보여요(정확도 97.8% 대 96.0%, 커버리지 30.3% 대 25.0%). 다만 test 597문항이라 단일 시드 차이라서 확정은 아니에요. 시드 반복(실험 5)이 필요해요.
- 두 모델 모두 엔진보다 못해요. 엔진은 같은 정확도 99%에서 커버리지 48%를 내요.

## 생성형 판정 (Qwen2.5 QLoRA 4bit, `train/train_gen.py`)

엔진 기준선은 같은 99%에서 커버리지 48.2%예요. 아래 값은 valid 문턱을 test에 적용한 결과예요.

| 실험 | 모델 | test 정확도 | ≥0.95 커버리지 / 정확도 | ≥0.97 커버리지 / 정확도 | ≥0.98 커버리지 / 정확도 |
|---|---|---|---|---|---|
| q05_e1 | Qwen 0.5B, 1 에폭 | 76.2% | 31.5% / 91.0% | 13.2% / 98.7% | - |
| q15_light | Qwen 1.5B, k=2, 1 에폭, max_len 768 | 73.7% | 45.6% / 95.2% | 15.9% / 100% | 15.9% / 100% |
| q15_v2 | Qwen 1.5B, k=2, layout 2, max_len 1024, rulings_file | 80.9% | 50.8% / 97.0% | 49.6% / 97.3% | 35.9% / 100% |

- 1.5B 학습은 20 스텝에 1.5~4시간 넘게 걸리는 구간이 있었고 원인은 아직 확인하지 못했어요. OOM은 없었어요.
- 세 실험 모두 엔진 단독(48.2% @ 99%)을 넘지 못했어요. q15_v2는 @98에서 35.9% 커버리지를 100%로 맞췄지만, 엔진과 같은 정확도에서 커버리지가 낮아요.
- 어댑터는 `digimon-judge-models` 저장소 `adapters/`에 올렸어요(q05_e1, q15_light, q15_v2 등).

## 이상한 점 / 코드 변경
- `train/train_yesno.py`: `klue/roberta-*`는 `type_vocab_size=1`인데 토크나이저가 `token_type_ids=1`을 넣어서 CUDA 인덱스 오류가 났어요. 모델이 받지 않는 `token_type_ids`를 제거하도록 고쳤어요(`USE_TT`). 이 수정 전에는 roberta-large 학습이 시작되지 않아요.
- 에폭 4가 에폭 3보다 나쁜 경우가 많아서 과적합 신호로 보여요. 선택은 valid로만 했어요.
- 데이터(`train/data`)와 `export_dataset.py`는 수정하지 않았어요.
- 모델 가중치는 커밋하지 않았어요(.gitignore).
