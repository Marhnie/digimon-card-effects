# 방법 (Methods) — 초안

## 2.1 데이터 수집과 정제
1. **카드 텍스트**: 한국어 공식 사이트 카드 리스트(292쪽, 5,824장)를 수집했다. 같은 카드 번호에 축약 재판 문구가 섞인 경우(532종) 가장 긴 문구를 정식 문구로 채택해 3,852종을 얻었다. 상단 텍스트(효과)와 하단 텍스트(진화원 효과·시큐리티 효과)를 구분해 보존했다.
2. **종합 룰**: 한국어판 Ver.4.3 docx의 자동 번호(numPr/ilvl)에서 조항 번호를 복원해 1,138개 조항을 얻었다(18장). 원본의 장 내부 참조 오류 15건(4장 번호 밀림)을 교정했다.
3. **공식 Q&A**: 카드 Q&A 5,308문항, 규칙 해설 Q&A 739문항을 수집했다. 카드 Q&A 중 답이 「네/아니요」로 시작하는 4,052문항(네 51.3%)을 정량 평가용 레이블로 썼다.
4. **문구 정규화(분류용)**: 같은 처리를 나타내는 옛·새 문구 10쌍을 통일했다. 예: 「DP를 +N 한다」→「DP +N」, 「시큐리티 어택」→「S 어택」, 「이 턴 동안」→「턴 종료까지」, 「N장 드로우한다」→「《N 드로우》」. 원문은 별도로 보존했다.

## 2.2 효과 단위 분할
카드 텍스트를 「독립적으로 발휘하는 효과」 단위로 나눴다. 경계는 다음과 같다.
- 문장 경계에 오는 효과 타이밍 묶음(【…】와 [턴 X회]·{패} 등 아이콘)
- 〔진화〕·〔조그레스〕 등 진화 조건, 디지크로스·어셈블리, 〈룰〉·〈링크〉
- 문장 경계의 단독 키워드

「」 안에서 언급된 다른 효과는 경계로 보지 않았다. 결과는 8,936개 효과 단위이다.

## 2.3 룰북 구조 분해 (핵심 기여)
종합 룰 15장 「효과의 룰」의 정의를 그대로 분해 체계로 썼다. 각 효과 단위를 아래 부품으로 나누고, 부품마다 근거 조항을 연결했다.

| 부품 | 판정 규칙(문구 신호) | 조항 |
|---|---|---|
| 출처 | 상단 텍스트 / 진화원 효과 / 시큐리티 효과 | 2-3-3, 15-3, 15-16-10 |
| 분류 4종 | 【메인】【카운터】→기동형; 유발 타이밍 또는 「~했을 때」→유발형; 「~할 때」「떠날 때」→즉시형; 지속 타이밍(【자신의 턴】 등)만 있거나 타이밍 없음→상재형 | 15-8 |
| 효과 타이밍 / 아이콘 | 【…】 / [턴 X회] {패} {트래시} {육성} {시큐리티} | 15-16, 15-14 |
| 유발 조건 | 첫 「~때,」 절. 단, 「있을 때·이하일 때」 등 상태 표현은 제외. 누가·어디서·무엇으로·무슨 일로 정규화 | 15-5 |
| 처리 조건 | 「~라면」 「~다면」 「~인 동안」 및 상태 「~일 때」 | 15-6 |
| 임의 처리 조건 | 「…하는 것으로」. 앞 문장 경계나 처리 조건까지를 한 덩어리로 봄 | 15-7 |
| 처리 | 마침표와 「그 후」로 단계를 나눔(「Lv.」 보호). 단계마다 처리 종류, 강제/임의(「할 수 있다」), 단일/전체(X마리/X장/까지/전부/이 카드), 대상 종류(디지몬·테이머·시큐리티·옵션 등)와 편(상대/자신/이 카드), 대상 필터(코스트·DP·Lv 이하/이상, 특징·명칭·색 지정, 진화원 조건, 레스트, 가장 높은/낮은), 지속 시간, 정보 추가·변경, 효과 부여, 치환(「대신」), 키워드 실행 | 15-1-2, 15-9, 15-10, 15-11, 15-12, 15-13, 18-2 |

규칙을 세운 근거는 다음과 같다.
- 유발형과 즉시형은 룰북이 「~할 때」를 즉시형으로 정의하고(15-8-5-1), 유발형의 예를 「~했을 때」로 든 데(15-8-3-1) 따라 시제로 가른다.
- 이미 유발·기동 타이밍이 있는 효과 안의 「~할 때」는 처리의 일부(예: 지연 코스트 감소)로 본다.
- 키워드 설명문(《키워드》(…))은 그 효과의 구조에서 빼되, 처리 단계에서 키워드를 실행하면 「키워드 실행」으로 기록한다.
- 진화 조건, 디지크로스, 〈룰〉은 룰북상 효과가 아니라 카드 정보(2-3)이므로 따로 분류한다.

**유발 조건 축**: 아이콘 유발 타이밍(15-16의 【등장 시】【진화 시】【소멸 시】【어택 시】【시큐리티】 등 15종)과 글로 쓴 유발 조건(15-5, 「~했을 때」)을 같은 축으로 본다. 분류는 하나로 정하되(【진화 시】【메인】 겸용은 기동형), 유발 조건 축에는 분류와 무관하게 유발 타이밍을 넣는다.

**구조 그룹**은 「분류 · (유발 조건 | 효과 타이밍) · 주 처리」로 정의한다. 주 처리는 「공개·덱 위 확인」을 제외한 첫 처리이다.

## 2.4 Q&A와 효과 연결
1. **1차**: 카드 Q&A를 그 카드의 효과 단위 중 하나에 배정한다. 질문에 나온 【타이밍】(×3)·키워드(×3)·진화원 효과/시큐리티 표기(×2)와 글자 2-gram 겹침(×4/|효과 2-gram|)으로 점수를 매기고, 효과가 하나뿐이거나 점수가 1.2 이상이면 배정한다.
2. **2차**:
   - 질문에 인용된 「구절」이 효과 원문에 그대로 있으면 그 효과에 배정한다.
   - 「진화 조건」, 「〈룰〉」, 「{패}」 같은 항목명이 나오면 해당 효과에 배정한다.
   - 그래도 남으면 「일반 판정」으로 보고, 가장 가까운 룰 조항(2-gram idf² 점수)에 연결한다.
3. **Q&A 쟁점 그룹**: 질문을 다음 특징으로 표현하고 코사인 평균 연결 응집 군집(거리 0.25)으로 묶는다.
   - 질문 템플릿(카드명·숫자·「이 카드」 정규화)의 글자 n-gram
   - 상황 슬롯(영역·사건·주체·방식·타이밍·부정)
   - 묻는 것(가능·유발·대상·순서·결과·정의 …)
   - 질문이 다루는 효과의 타이밍·유형

## 2.5 판정 방식 (평가 대상)
| 방식 | 내용 |
|---|---|
| 같은 상황 선례 | 묻는 것과 상황 슬롯 집합이 완전히 같은 Q&A. A 같은 효과 패턴 → B 같은 효과 유형 → C 그 밖 순서로 찾고, 부정 질문이면 답을 뒤집는다 |
| 비슷한 질문 | 질문 글자 2-gram Jaccard(같은 카드 +0.12, 같은 패턴 +0.08) 상위 5개의 유사도³ 가중 투표 |
| 쟁점 그룹 | 가장 가까운 질문이 속한 쟁점 그룹의 다수 답 |
| ML 결합 | kNN·질문 문장 로지스틱·패턴/유형 사전 비율을 로지스틱 스태킹 |
| LLM | Claude에 카드 텍스트, 질문, 근거(위 방식들이 찾은 Q&A와 연결 조항)를 주고 JSON으로 판정받는다 |
| 하이브리드 | 확신 높은 선례(A·만장일치)는 엔진이 답하고, 나머지만 LLM에 넘긴다 |

## 2.6 평가 프로토콜
- **레이블**: 공식 카드 Q&A 답의 첫 단어(네/아니요).
- **누설 차단**: 평가 문항 자신과, 같은 카드에서 유사도 0.55를 넘거나 전체에서 0.92를 넘는 재진술은 근거·이웃에서 뺐다. 교차검증은 이 기준의 연결 요소를 그룹으로 하는 GroupKFold(5)로 했다.
- **LLM 시험**: 100문항(네 50 / 아니요 50, seed 20261017)을 4방식으로 풀었다. 판정은 웹 접근을 막은 Claude 하위 에이전트가 맡고, 같은 근거 파일을 쓰게 했다.
- **LLM 시험 확대(E18)**: 겹치지 않는 200문항(네 100 / 아니요 100, seed 20261018)을 S2·S3·S5(판정 도우미 v4 근거)로 다시 풀고, 정확도의 Wilson 95% 신뢰구간과 방식 간 정확 McNemar 검정을 보고한다. 두 시험에 모두 있는 방식은 300문항으로 합산한다.
- **지표**: 정확도, 커버리지(엔진이 답한 비율), 확신 구간별 정확도.
- **한계**: 300문항 합산에서도 98% 수준의 차이(검색 근거 대 구조 근거)는 가를 수 없다(불일치 쌍 2개). 「네/아니요」형이 아닌 질문(정의·순서·결과, 약 15%)은 정량 평가에서 빠졌다.

## 2.7 네트워크 분석
### 2.7.1 효과 노드 네트워크
노드는 카드 효과 7,791개(카드 정보 제외)이다. 링크는 이유별 점수를 따로 가지며, 한 쌍에 이유가 여러 개면 독립 근거로 보고 합친다: 강도 = 100·(1−∏(1−점수)).

| 이유 | 만드는 방법 | 점수 |
|---|---|---|
| 구조 유사 (s) | 구조 부품 토큰(분류·출처·타이밍·유발 조건×2·처리 조건·임의 처리 조건·처리·대상·편·필터·키워드) TF-IDF와 문구 템플릿 글자 2~3-gram(가중 0.5)의 코사인; 노드마다 상위 8개, 코사인 0.35 이상 | 0.2~0.9 (코사인 0.35~1 선형) |
| 같은 문구 (s) | (구조 그룹, 정규화 문구)가 같은 효과 3개 이상을 고리로(다음 2개) 연결 — 동점 kNN이 같은 문구를 여러 덩어리로 끊는 것을 막음 | 0.9 |
| 같은 처리 (p) | 처리 단계 키 (처리, 대상 종류, 필터 집합)가 같은 단계끼리, 다른 카드의 가장 닮은 10개 | 0.35+0.35·유사도+0.1(같은 편)+0.05(필터 있음) |
| 같은 유발 조건 (t) | 유발 조건 축 값이 같은 효과끼리 가장 닮은 5개 | 0.5+0.5·유사도 |
| 같은 Q&A 쟁점 (q) | 쟁점 그룹(거리 0.25) 크기 2~20 | 0.9(≤8) / 0.7 |
| 같은 카드 (c) | 한 카드의 효과들 | 0.35 |
| 이름 언급 (m) | 효과 문구의 「카드명」 → 그 카드의 효과, 최대 10개 | 0.45 |

결과: 링크 104,118개(이유: 구조 48,218 · 같은 처리 37,143 · 유발 조건 19,583 · 이름 언급 15,121 · 같은 카드 5,887 · Q&A 2,800). 중심성은 가중 PageRank.

### 2.7.2 클러스터링과 해상도 선택
- **세부 클러스터**: 가중 Louvain. 해상도 γ를 0.2~5.0에서 바꾸며 시드 10회씩 돌려 ① 모듈성 Q(γ=1 기준), ② 시드 간 AMI(안정성), ③ 이웃 γ 간 AMI(고원), ④ 귀무 모형(차수 보존 재배선 + 가중치 섞기 3회)의 Q를 본다. Q가 최댓값에서 0.003 이내인 구간 중 시드 안정성이 가장 높은 γ = **1.6**(Q 0.733, 귀무 0.145, 시드 AMI 0.886)을 택했다 → 57개.
- **대분류**: 세부 클러스터를 점으로 한 클러스터 그래프 위의 재분할은 실제 Q(해상도 0.8~3.5에서 0.02~0.13)가 귀무(0.13~0.20)보다 모든 해상도에서 낮아 자연 구조가 없다고 보고 버렸다. 대신 효과 그래프 자체를 낮은 해상도로 나누고(γc = **0.4**: Q 0.694, 시드 AMI 0.78), 세부 클러스터는 효과가 가장 많이 속한 대분류에 넣는다(포함 순도 0.89) → 22개. γc < 0.3에서는 Q가 급락(0.39)한다. 대분류는 안정성이 세부보다 낮아 상위 참고 묶음으로 쓴다.
- **외부 기준과의 일치**: 세부 클러스터와 구조 그룹(1,067개)의 AMI 0.60, 분류 4종과 0.25 — 클러스터는 '분류'보다 '처리 내용'을 따라 묶인다.
- **이름**: 구성원에 많이 나오는 요소로 자동 요약을 만든 뒤, 사람이 이름을 붙였다(크기가 같을 때만 적용).
- **배치**: 대분류 그래프 spring → 대분류 안에 세부 클러스터 원을 모아 놓고(대분류 중심으로 당기며 겹침 제거) → 구성원은 원 안을 고르게 채운다(각도는 spring, 반지름은 순위).

### 2.7.3 보조 네트워크
효과 요소 공동 출현 네트워크(PMI 0 초과, 5회 이상), 패턴 네트워크, Q&A kNN 네트워크와 이종 네트워크의 개인화 PageRank(근거 순위에서는 문구 유사도가 우세 — 01_연구기록 참조).

## 2.8 판정 도우미에서의 활용
고른 효과의 룰북 구조(2.3)와 세부 클러스터를 화면에 보여 주고, 같은 세부 클러스터에 속한 다른 카드 효과들의 Q&A를 「같은 효과 무리 Q&A」로 질문 유사도 순으로 낸다. LLM에 넘기는 근거에도 같은 무리 Q&A와 구조 요약을 넣는다.

## 2.9 시간 분할 평가 (RQ4)
E19부터 판정 평가는 2.6의 교차검증 대신 시간 분할로 한다. 최신 제품(BT22·BT23·BT24·EX9·EX10·ST21·ST22)의 카드 Q&A를 시험으로, 그 이전 제품의 Q&A를 근거로 쓴다. 판정기는 최신 제품 Q&A를 보지 못한다. 후속 절의 「최신 팩」은 이 시험 구간을 뜻한다.

시험 표본은 목적에 따라 다음과 같이 다르며, 표본이 다른 수치는 직접 비교하지 않는다.

| 표본 | n | 정의 | 사용 |
|---|---|---|---|
| 네/아니요 전체 | 597 | 최신 팩 네/아니요 문항 | 오프라인 평가(엔진, 의미 검색, 생성 모델) |
| 페이지 시험 | 445 → 536 → 557 | 판정 페이지에 넣어 채점한 문항. BT24 카드 보충(E28)으로 536, Q&A 연결 확대(E30)로 557이 되었다 | 2.10의 판정 경로 평가 |
| 엔진 미달 | 309 | 엔진 확신 0.80 미만인 문항(최대 확신 0.797) | 2.11의 실행 시험 |
| 판정 보류 | 294 | 페이지 시험 557문항 중 페이지가 보류한 문항 | 추가 신호 탐색, 2.13의 보완 평가 |
| 구어체 판정 대상 | 120 | 구어체 시험 세트 200문항 중 판정 대상(E53) | 2.14 |

- **카드 데이터 보충**: BT24는 평가 시점에 공식 사이트에 카드가 없어 페이지에서 고를 수 없었고, 공식 Q&A 158개가 효과와 연결되지 않았다. 반다이 번역완료 워크북에서 115장(BT24 102장, P 카드 13장)을 옮겨 효과 단위를 8,936개에서 9,317개로 늘렸다. 기존 효과의 순서와 내용은 바꾸지 않았다(E28).
- **지표**: 판정 범위(답한 문항 / 시험 문항)와 답한 문항의 정확도를 「범위 @ 정확도」로 적는다.
- **문턱 선택**: 시험 문항에서 문턱을 고르면 낙관적이다. 그래서 시험 제품을 절반으로 나눠 한쪽에서 고르고 다른 쪽에서 재거나, valid에서 고른다. 이 절차를 지키지 못한 경우는 해당 절에 밝힌다.
- **운영과의 차이**: 실제 운영에서는 최신 팩 Q&A도 근거로 들어가므로 시간 분할 수치는 운영 판정률보다 낮을 수 있다(E19, E44).

## 2.10 선택적 판정 페이지 (RQ2, RQ4)
판정 페이지는 모든 질문에 답하지 않고, 근거가 있는 경로에서만 답한 뒤 나머지를 「판정 보류 · 심판 확인 필요」로 둔다. 배포판의 판정 경로에는 LLM 호출이 없다(E25). 보류 질문은 운영자의 Claude 초안을 거쳐 심판이 확인하며(E41), 이는 LLM이 판정이 아니라 초안 단계에 놓인다는 뜻이다.

### 2.10.1 판정 경로와 문턱
경로는 다음 순서로 적용하고, 앞 경로가 답하면 뒤 경로는 쓰지 않는다. 입력이 공식 질문이면 그 공식 답을 먼저 보여 준다.

| 순서 | 경로 | 답하는 조건 | 문턱을 정한 방법 |
|---|---|---|---|
| 1 | 공식 선례 | 묻는 것과 상황 슬롯이 같은 이전 Q&A 중 같은 효과 패턴 또는 같은 룰북 구조(E43 추가)에서 답이 만장일치 | 문턱 없음(일치 규칙) |
| 2 | 확인된 판정 | 주 카드와 함께 고른 카드가 같고, 질문 2-gram Jaccard 0.6 이상(같은 효과면 0.45 이상). 부정 정렬이면 답을 뒤집는다 | 고정값(E21) |
| 3 | 룰 쟁점 | 질문 신호 규칙에 걸리고, 예시 Q&A의 답이 모두 같음 | 만장일치(E19a는 예시 3건 이상) |
| 4 | 엔진 | 엔진 확신 0.80 이상 | 고정값(2.10.4) |
| 5 | 의미 검색(서버판) | 융합 순위 1위 Q&A의 코사인 0.885 이상. 그 답을 부정 정렬해 쓴다 | 절반 분할 중 엄격한 값(2.12.4) |

확인된 판정은 심판이 쌓는 운영 데이터이고, 2.10.5의 경로별 수치에는 나오지 않는다. Claude 답을 사람이 저장한 판정에는 `src:'claude'`를 표시하며, Claude 없는 성능을 잴 때는 이를 뺀다(E40).

### 2.10.2 선례와 상황
선례 규칙은 「같은 효과」와 「같은 상황」을 함께 요구한다. 두 조건의 역할을 다음과 같이 쟀다.
- **같은 효과의 확장(E43)**: 분류, 유발 조건, 처리 조건 유무, 처리 단계의 행동·편·대상·필터가 같으면 문구가 달라도 같은 효과로 보았다. 확정 선례는 113문항에서 115문항으로 늘었고(추가 2/2 정답), 페이지 시험의 전체 범위는 변하지 않았다.
- **상황 조건 해제(E43)**: 묻는 것과 상황이 같은 이전 Q&A가 있는 문항은 557문항 중 227문항이다. 상황 조건을 풀고 같은 효과만 보면 91문항에 근거가 생기지만 답이 전부 같아도 정확도는 54%이고, 상황 겹침 0.67 이상에서도 85%이다.
- **상황 항목 완화(E44)**: 같은 효과 패턴·같은 묻는 것인 이전 팩 Q&A 쌍 11,057개로 로지스틱 회귀를 학습해 상황 항목 61개 중 답을 바꾸지 않는 항목을 찾았다. 이 쌍들의 답 일치율은 62%이다. 계수 0.3 이상 10개를 빼면 확정이 115에서 116문항(100%)으로 늘고, 0.1까지 빼면 120문항이지만 오답이 4개 생긴다. 효과가 1문항이어서 페이지에는 적용하지 않았다.

### 2.10.3 룰 쟁점
룰 쟁점은 질문 신호 정규식, 묻는 형태, 제외 신호, 근거 조항, 답에 그 원리를 쓴 공식 Q&A 예시로 이루어진다(E19a). 쟁점을 알아보면 조항과 예시를 근거 맨 앞에 두고, 예시의 답이 모두 같을 때만 판정한다.
- **자동 추출 불채택(E32)**: 이유 묶음마다 질문의 공통 표현을 AND로 묶은 후보는 최신 팩 16.2% @93.0%(정밀도 0.97 이상, 지지 5건 이상), 9.4% @96.4%(0.99, 10건)였고, 엔진이 확신하지 못한 문항에서는 75~78%였다.
- **원리 기반 추가**: 질문 문형으로 예시를 찾는 규칙 6개를 더했다(E32, 예시 6~33건). 규칙을 고를 때 최신 팩 일치 건수도 함께 보았으므로 이 결과는 약간 낙관적이다. 이어서 이전 팩 질문만 보고 7개를 더 썼다(E44, 이전 팩 예시 n 12~68, 답 일치). 다만 후보였던 「어떤 진화든 진화 드로우」는 최신 팩에서 새로 판정하는 1문항을 틀려서 뺐다.

### 2.10.4 엔진 결합
엔진은 근거 신호를 결합해 답과 확신도를 낸다.
- **기준선(E19)**: E4의 신호에 같은 무리·유발 조건·구조 그룹 투표를 더한 로지스틱 모델은 597문항 전체 80.1%이고, 정확도 95%를 유지하는 범위는 24.8%, 97%는 23.1%이다.
- **이유 묶음(E19)**: 공식 답변의 이유 문장을 템플릿화해 코사인 평균 연결 0.35로 묶었다. 전체 215묶음(3건 이상, 카드 2장 이상) 1,803문항이고, 네/아니요 일관 90% 이상은 111묶음 911문항이다.
- **엔진 라이트(E19)**: 브라우저가 계산할 수 있는 신호만 쓴다. 2-gram Jaccard 상위 10, 부정 정렬, 투표·최고 유사도·일치율·고유사 개수, 이유 묶음 투표·강도, 같은 효과 무리 투표, 같은 카드 투표를 입력으로 하고, 답 로지스틱과 「이 답이 맞을 확률」을 예측하는 정답 여부 로지스틱을 따로 둔다. 전체 정확도는 78.4%이다.
- **문턱**: 시험에서 고른 문턱은 절반 분할에서 민감했다(0.654 → 61%·90.3%, 0.734 → 62%·99.2%). 그래서 고정 문턱 0.80을 택했고, 597문항 전체 48.2% @99.0%, 절반별 58%·100%와 43%·98.2%였다. 고정값을 정할 때 시험 절반의 결과를 보았으므로 이 수치는 완전한 표본 외 추정이 아니다.
- **구현 검증**: 브라우저 구현을 445문항에서 Python과 대조했다. 답 일치 98.7%, 확신 차이 중앙값 0이고, 엔진 판정은 47.9% @98.1%이다.

## 2.11 규칙 실행 엔진(DCGO) 시험 (RQ4)
공개 룰 엔진 DCGO(DCGO2/DCGO-Card-Scripts, MIT, 카드 3,664장)가 판정의 근거가 될 수 있는지를 세 단계로 쟀다.
1. **정적 활용(E20)**: 스크립트를 실행하지 않고 읽어 10,565개 효과 블록의 아이콘, 턴 1회, 임의 여부, 선택 생략, 최대 미만 종료, 재확인을 뽑았다. 카드 단위 대조에서 주요 아이콘 6종 조합은 96.8% 일치했다(한글 3,659장 중 3,508장 대조). 그러나 생략형 질문 539개 중 394개를 판정한 정확도는 54%였다.
2. **실행 시험 장치(E22)**: DCGO(Unity 2021.3.45f2)를 `-batchmode`로 실행한다. 작업 JSON에 패·트래시·시큐리티·필드 스택·메모리와 단계(play/digivolve/attack/activate/optional/pass)를 넣으면, 보드를 주입해 실행하고 효과 로그와 최종 상태를 저장한다. 한 건에 약 1~1.5분이 걸린다. 최신 팩 단일 카드 문항 11개를 손으로 시나리오로 옮긴 시범에서 8/11(73%)이 공식 답과 일치했다.
3. **자동 변환(E23)**: 엔진 미달 309문항을 Sonnet 서브에이전트가 20문항씩 시나리오로 변환했다. 입력은 질문, 카드 본문, 지침(스키마, 판정 규칙 DSL, 손으로 만든 예시)이고, 공식 답은 넣지 않았다. 다만 정답 파일 열람은 지시로 금지했을 뿐 기술적으로 막지 못했다. 변환 결과는 검증 스크립트로 문법·카드 존재·스키마를 확인했고, 판정 규칙 DSL을 기계적으로 평가했다.

자동 변환 결과는 다음과 같다.
- **범위**: 변환 가능 35/309(11.3%). 재현 불가 274문항의 사유는 상대 턴·턴 시작/종료 72, 복수 카드 상호작용 68, 진화원·{패} 효과 54, 선택 지정 필요 41, 기타 39이다. 사유 분류도 LLM 판단이고 표본 검수는 하지 않았다.
- **정확도**: 실행 성공 35/35, 공식 답과 일치 27/35 = 77.1%(Wilson 95% 61.0–87.9%). 공식 답 「네」 25/29, 「아니요」 2/6이다. 변환 에이전트가 불확실을 표시하지 않은 문항은 21/24, 표시한 문항은 6/11이며, 이 구분은 사후 분석이다.
- **오답 원인**: 불일치 8건을 로그와 대조해 판정 규칙 오류 5건, 시나리오 변환 오류 1건, DCGO 구현 차이 2건으로 분류했다. 구현 차이 2건은 버그 후보이며 확정하지 않았다.
- **유효성**: 진화 직후 프레임 대기가 끝나지 않아 【진화 시】 효과가 발동하지 않은 1차 실행(14/33)은 무효로 처리하고 결과만 보존했다. 위 수치는 결함을 고친 2차 실행의 값이다.

이 정확도로 그대로 합치면 전체 정확도를 떨어뜨리고, 변환 단계에 LLM 호출이 필요하다. 실행 엔진은 2.10의 판정 경로에 들어 있지 않다.

## 2.12 구어체 시험 세트와 의미 검색 (RQ3)
### 2.12.1 시험 세트
- **구어체 시험 세트(E31)**: 최신 팩 공식 질문 중 25~170자인 것에서 200문항을 무작위로 골랐다(이유 묶음이 있는 것 100, 없는 것 100). Sonnet 서브에이전트 4개가 6가지 말투(반말+줄임말, 오타, 카드명 축약+은어, 상황을 길게 풀어쓴 구어체, 존댓말 커뮤니티체, 초단문 키워드식)로 바꿨다. 에이전트에게는 질문, 카드명, 말투만 주었고 공식 답변은 보여 주지 않았다. 이 세트는 학습에 쓰지 않았고, 사전 작성과의 관계는 아래 개발 세트 항목에 적었다.
- **개발 세트**: 사전과 가중치를 정하려고 같은 방식으로 BT15~BT21·EX5·EX6·EX8 질문 120개를 따로 만들었다. 사전을 처음 쓸 때 평가 세트 앞 14문항을 은어 파악용으로 훑어보았으나, 점수를 보고 규칙을 평가 세트에 맞춰 고치지는 않았다.
- **모호 세트(E38)**: 구어체 평가 문항의 공식 문장에서 이름·번호를 지우고 묻는 절과 짧은 세부 하나만 남겼다(n=87). 학습에 쓴 생성 규칙과 같은 방식이므로, 실제 이용자 질문에서의 이득은 더 작을 수 있다.
- **커뮤니티 질문(E39)**: 사용자가 직접 모은 370개이다. 답이 없어 정확도는 재지 못하고 연결 점검에만 쓴다. 로컬에만 두고 공개 저장소에 올리지 않는다.

구어체 문장은 LLM이 원문을 바꿔 쓴 것이므로 실제 이용자 말투와 다를 수 있다.

### 2.12.2 정규화와 검색 평가
사전 정규화(qnorm)는 시점·키워드·용어·끝맺음 규칙 82개와 공식 카드명 사전을 쓴다. 카드명은 공식 이름의 유일한 접두일 때만 늘리고, 근거 없는 약칭은 확정하지 않는다. 질문 틀은 대상 카드, 타이밍·키워드, 상황, 묻는 것으로 나눈다.

검색 대상은 BT22 이전 공식 Q&A와 같은 카드의 Q&A이다. 정답은 이유 묶음이 같고 답의 방향이 같은 Q&A, 또는 문장이 똑같은 Q&A이다. 평가는 두 가지로 한다. A는 원문 Q&A를 검색 대상에 두어 이미 있는 질문의 바꿔 말하기를 재고(n=200), B는 원문을 빼고 같은 이유 묶음만 정답으로 두어 처음 보는 질문의 일반화를 잰다(n=101).

| recall@1 | 2-gram | 정규화 | 정규화+틀 | 상한(공식 문장, 2-gram) |
|---|---|---|---|---|
| A (n=200) | 0.855 | 0.865 | 0.875 | 1.000 |
| B (n=101) | 0.703 | 0.713 | 0.743 | 0.851 |

개발 세트(n=120)에서는 정규화가 오히려 약간 낮았고(A@1 0.892 → 0.850, B@1 0.863 → 0.836), 평가 세트의 이득은 오차 범위(±4%p 안팎)이므로 정규화의 우위를 결론으로 삼지 않는다.

### 2.12.3 의미 검색 모델과 RRF 결합
- **모델(E31)**: jhgan/ko-sroberta-multitask를 대조학습으로 미세 조정한다. 긍정 쌍은 이유 묶음과 답 방향이 같은 쌍 등이고, 어려운 부정은 문장이 비슷한데 답이 반대인 쌍이다. 3에폭, 배치 16, 학습률 2e-5, 3중쌍 5,981개이고, 평가 세트와 최신 팩 Q&A는 학습에서 뺐다.
- **서버 모델**: CPU로 같은 레시피를 다시 학습한 모델(구어체 단독 @1 0.816, GPU 모델 0.828)을 쓴다.
- **결합(E31 추가 2)**: 모델 코사인 순위와 2-gram 순위를 파라미터 없는 RRF로 합친다. 가중합 α는 선택에 쓸 개발 세트가 없어(원문이 학습 풀에 있음) 참고값으로만 본다.
- **평가 표본**: 학습 풀에서 평가 문항을 빼고 정답 묶음이 말뭉치에 남은 문항만 세므로 구어체는 n=87이다. 2.12.2의 n=101과 말뭉치 정의가 달라 직접 비교하지 않는다.

| 방식 | 구어체 @1 / @3 / @10 (n=87) | 최신 팩 공식 @1 / @3 / @10 (n=314) |
|---|---|---|
| 2-gram | 0.770 / 0.862 / 0.931 | 0.924 / 0.955 / 0.990 |
| 모델 | 0.816 / 0.908 / 0.977 | 0.911 / 0.936 / 0.990 |
| RRF | **0.874 / 0.931 / 0.989** | 0.917 / 0.949 / 1.000 |

n=87의 오차는 ±7%p 안팎이다. 또한 동점 처리에 따라 2-gram 값이 달라지므로(GPU 보고의 구어체 @1은 0.713) 같은 스크립트 안의 값끼리만 비교한다.

모호 질문은 재학습 모델을 더한 3중 RRF(기존 모델, 모호 학습 모델, 2-gram)로 다룬다. 모호 학습 모델로 그대로 바꾸면 구어체와 시간 분할 성능이 떨어졌으므로(RRF @1 구어체 0.874 → 0.828, 시간 분할 0.917 → 0.901), 기존 성능을 유지하는 3중 결합을 택했다. 같은 비교 안에서 모호 @1은 0.540 → 0.644, @3은 0.782 → 0.851로 올랐고, 시간 분할 @1은 0.917 → 0.914(n=314), 구어체 @1은 0.885 → 0.874(n=87)로 각각 1문항 차이였다(E38).

별명은 사용자가 확인한 사전(aliases.json)으로 공식 표기에 대응시킨다. 커뮤니티 질문 370개에서 카드 인식은 124개에서 143개로 늘었다. 가장 가까운 공식 Q&A 코사인은 중앙값 0.48이고 판정 문턱 0.885 이상은 0개였다(E39). 커뮤니티 질문에서는 의미 검색 판정이 아직 작동하지 않는다는 뜻이다.

### 2.12.4 의미 검색을 판정에 쓰기 (RQ4)
이전 팩 공식 Q&A 중 융합 순위 1위의 답을 부정 정렬해 쓴다(E37). 문턱은 신상품을 절반으로 나눠 한쪽에서 고르고 다른 쪽에서 쟀으며, 양쪽 중 엄격한 코사인 0.885를 고정했다. 느슨한 쪽 0.707은 반대쪽에서 93.9%로 떨어져 쓰지 않았다. 597문항에서 289문항에 답해 정확도 99.0%이고, 엔진이 답하지 못한 문항 중 27개를 더 답해 모두 맞았다. 3중 융합에서도 이 문턱은 첫 모델의 코사인 그대로 쓴다(E38). 서버 실측은 2.10.5에 있다.

## 2.13 생성 모델 q15_v2 (RQ4)
판정 보류 질문에 쓸 수 있는 자체 모델을 시험한다. 앞서 판별 모델(roberta-large cross-encoder, 입력에 선례 포함)을 쟀으나 시드에 따른 편차가 컸고(전체 정확도 81.4/76.5/76.7%, valid 문턱 @97의 시험 정확도 97.8/91.0/98.1%, n=597), 엔진과 합쳐도 늘어나는 폭이 작았다(E27). 생성 모델은 외부 API 없이 직접 돌릴 수 있도록 작은 공개 모델을 미세 조정한다(E52, 대상 GPU는 GTX 1660 SUPER 6GB).

- **모델**: Qwen/Qwen2.5-1.5B-Instruct를 QLoRA 4비트로 미세 조정한다. 어댑터만 저장하고 체크섬으로 확인한다.
- **데이터**: 시간 분할을 그대로 쓴다. 근거 Q&A는 이전 팩에서 고르고 자기 자신은 뺀다. 학습은 3,947건에 확인 판정 79건을 더한 4,026건이고, 최신 팩 카드가 들어간 확인 판정 48건은 시험을 지키려고 뺐다. 시험은 네/아니요 597문항이다.
- **출력**: 공식 답변 말투(「네, …」/「아니요, …」/설명)로 생성하고, 정확도는 첫 단어로 잰다.
- **프롬프트 형식 2**: 카드 → 근거 Q&A → 질문 순서로 놓아 질문을 맨 뒤에 둔다. 근거 Q&A는 2개, 최대 길이는 1024토큰이다. 이전 형식에서는 질문이 맨 앞에 있었고, 768토큰에서 시험 프롬프트의 30%(179/597)가 넘쳐 앞에서부터 잘렸다. 그 결과 43문항은 질문 첫머리까지 사라졌다(q15_light).
- **확신도**: 첫 토큰에서 네와 아니요의 확률을 비교한다. 확신도는 max(P(네), 1−P(네))이고, P(네) ≥ 0.5이면 네로 답한다.
- **문턱**: valid에서 95·97·98% 목표별로 고르고 시험에는 고정해 적용한다. q15_v2의 문턱은 95% 0.9396, 97% 0.9502, 98% 0.9873이다.

| 모델 | 전체 정확도 (n=597) | 95% 목표 | 98% 목표 |
|---|---|---|---|
| 0.5B q05_e1 | 77.2% | 4.5% @92.6% (27문항) | 없음 |
| 1.5B q15_light | 73.7% | 45.6% @95.2% | 15.9% @100% (95/95) |
| 1.5B q15_v2 | 80.9% | 50.8% @97.0% | 35.9% @100% (214/214) |

**보완 평가(complement_eval.py)**: 모델이 페이지가 보류한 문항을 얼마나 더 답하는지를 페이지 시험 557문항에서 쟀다. 페이지는 263문항(47.2%)을 98.5%로 판정한다. 둘 다 답한 문항에서 모델과 페이지의 답은 99.5~100% 일치한다. 구간은 stats_ci.json의 Wilson 95%이다.

| 문턱 | 보류 문항에 더 답함 | 정확도 (Wilson 95%) | 페이지와 합친 범위 @ 정확도 |
|---|---|---|---|
| 95% 목표 (0.9396) | 36/42 | 85.7% (72.2–93.3%) | 54.8% @96.7% |
| 97% 목표 (0.9502) | 36/42 | 85.7% (72.2–93.3%) | 54.8% @96.7% |
| 98% 목표 (0.9873) | 20/20 | 100% (83.9–100%) | 50.8% @98.6% |

valid에서 정한 95·97% 목표는 보류 문항에서 지켜지지 않았다. AI 의견은 보류된 질문에서만 쓰이므로 서버의 기본 문턱은 가장 엄격한 0.9873으로 둔다. 학습 방식(형식 2)은 같은 시험에서 q15_light 결과를 본 뒤에 정했으므로 20/20은 약간 낙관적일 수 있다.

## 2.14 질문 번역 (RQ3)
구어체를 공식 문체로 옮기면 판정 경로를 그대로 쓸 수 있는지를 잰다(E53).
- **상한 측정**: 구어체 시험 세트 중 판정 대상 120문항을 Claude 없이, 이전 팩만 근거로 판정했다. 공식 문체로 물으면 56/120(46.7%)에 98.2%(선례 21/21, 엔진 28/29, 쟁점 6/6)이고, 같은 질문을 구어체로 물으면 1/120(0.8%)이다.
- **번역 말뭉치**: LLM 없이 규칙으로 만들었다. 이전 팩 공식 질문을 정답으로 두고, 「이 카드」를 카드 이름이나 별명으로 바꾸고 카드 번호를 지운 뒤 구어체화·모호화를 적용해 원문을 만든다. train 7,889, valid 801(카드 기준 분할)이고, test는 구어체 시험 세트 200문항으로 학습에 쓰지 않았다.
- **신경망 번역기**: 판정 모델과 같은 QLoRA 기반이고, 시스템 지시로 판정을 금하고 질문만 공식 문체로 옮기게 했다. 번역문을 판정 경로에 다시 넣어 판정률·정확도를 재고, 시험 200문항의 문자 2-gram 유사도를 함께 본다.
- **규칙 정규화**: 사전 정규화(2.12.2)에 선택한 카드 이름·별명을 「이 카드」로 바꾸는 단계를 더했다.
- **순차 판정**: 정규화만 쓰면 공식 문체가 조금 바뀌어 전체 557문항의 범위가 47.2%에서 46.3%로 줄었다. 그래서 정규화본으로 먼저 판정하고, 판정하지 못하면 원문으로 한 번 더 판정한다.

| 방법 (구어체 120문항) | 판정 | 정답 |
|---|---|---|
| 구어체 그대로 | 1 (0.8%) | 기록 없음 |
| 사전 정규화 | 2 (1.7%) | 기록 없음 |
| 0.5B 번역기 q05_tr | 3 (2.5%) | 3/3 |
| 사전 정규화 + 카드명 → 「이 카드」 | 9 (7.5%) | 9/9 |
| 위 방법 + 순차 판정 | 10 (8.3%) | 10/10 |
| 공식 문체 (상한) | 56 (46.7%) | 55/56 |

0.5B 번역기는 원문에 없는 카드와 상황을 지어내거나 문장을 반복하는 경우가 많았고, 2-gram 유사도는 0.237에서 0.290으로 오르는 데 그쳤다. 그래서 판정 화면에는 규칙 정규화와 순차 판정만 넣었으며, 공식 문체 120문항과 전체 557문항의 수치는 변하지 않았다. 표본이 작으므로 정답 수는 경향으로만 읽는다.

## 2.15 사전 등록 규칙과 BT25 예행 (RQ3, RQ4)
### 2.15.1 사전 등록 규칙
2.10.6의 탐색과 2.13의 보완 평가는 같은 시험 구간을 반복해 보았으므로 일반화 수치로 삼기 어렵다. 이를 가르기 위해 판정 보류 문항에만 적용할 규칙을 새 팩 Q&A가 나오기 전에 고정했다(paper/results/preregistered_rules.json). 이 파일은 수정하지 않고, 바꿀 일이 있으면 새 항목을 더한다.

| 규칙 | 등록일 | 규칙 | 출처 | 성공 기준 |
|---|---|---|---|---|
| R1 | 2026-10-22 | 엔진 확률 max(p, 1−p) ≥ 0.8이고 의미 검색 1위 코사인 ≥ 0.8이며 두 답이 같으면 답한다 | E46 참고 규칙. BT22~ST22 보류 문항 14/14, 1,793개 조합에서 고른 값이라 다중 비교 편향이 있다 | BT25(또는 다음 세트) 공식 네/아니요 Q&A, 이전 제품 전부를 근거로 n ≥ 10, 정확도 ≥ 97% |
| R2 | 2026-10-27 | 자체 모델 q15_v2의 첫 토큰 확신도 ≥ 0.9873이면 P(네) ≥ 0.5일 때 네, 아니면 아니요로 답한다 | valid의 98% 목표 문턱. BT22~ST22 보류 294문항 중 20문항 추가, 20/20 | 페이지가 보류한 BT25(또는 다음 세트) 공식 네/아니요 Q&A에서 n ≥ 10, 정확도 ≥ 97%. 통과해야 페이지에 자동 판정으로 표시할 수 있다 |

R2의 모델은 어댑터 zip의 sha256으로, 문턱은 0.9873으로 고정했고, 채점 순서는 train/prereg_r2.py에 있다. R1의 한 세대 전 팩 검증은 엔진 가중치와 의미 검색 모델이 그 팩으로 학습되어 있어 공정하지 않아 하지 않았다(E46).

### 2.15.2 BT25 예행(E55)
한국 공식 사이트에 BT25 Q&A가 없어 일본판 Q&A의 임의 번역으로 예행했다. 이는 탐색용이며 사전 등록 시험이 아니다.
- **자료**: 기존 BT25 미발매 Q&A 번역(75장 262문항, 공식 Q&A 문체)을 쓴다. 카드는 일본 카드 본문 104장을 서브에이전트 3개가 임시 번역했고(`source: jp-unofficial`, 불확실 49장 기록), 신규 메커니즘은 직역이다. 작업은 저장소 복사본에서만 했다.
- **표본**: 네/아니요형 163개 중 효과에 연결된 139개이다. 구어체는 서브에이전트가 공식 문체 질문을 E53과 같은 6가지 문체로 바꾼 것이다(답변은 보지 않음).
- **채점**: 규칙·문턱·모델은 그대로 두고, BT24 이전 모든 팩을 근거로 했다. 보류는 판정 화면(tests/tdec.js) 기준이다.

구간은 stats_ci.json의 Wilson 95%이다. R1 공식 문체 3/3과 「화면 + R2」는 stats_ci.json에 구간이 없다.

| 질문 문체 (n=139) | 판정 화면 범위 | 화면 정확도 (Wilson 95%) | 보류 | R1 | R2 | 화면 + R2 |
|---|---|---|---|---|---|---|
| 공식 문체(번역) | 85/139 = 61.2% | 84/85 = 98.8% (93.6–99.8%) | 54 | 3/3 → 기준 미달(n<10) | 2/2 (34.2–100%) → 기준 미달(n<10) | 87/139 = 62.6% @98.9% |
| 구어체 | 21/139 = 15.1% | 20/21 = 95.2% (77.3–99.2%) | 118 | 7/7 (64.6–100%) → 기준 미달(n<10) | 16/16 (80.6–100%) → 수치상 기준 충족 | 37/139 = 26.6% @97.3% |

판정 화면의 오답은 두 문체 모두 같은 1문항(BT25-080, 룰 쟁점 경로)이다. 성공 판정에 쓰지 않는 참고값으로, R2 문턱을 0.95로 낮추면 공식 문체 보류는 7/9, 구어체 보류는 40/42이고, 보류 전체 정확도는 각각 63.0%(n=54), 78.0%(n=118)이다.

이 결과로 R2 성공을 선언하지 않는다.
- Q&A와 카드 본문이 비공식 번역이므로, 한국 공식 문구가 나오면 결과가 달라질 수 있다.
- R2의 등록 범위는 공식 네/아니요 Q&A이고, 그 범위의 결과는 2/2로 n이 모자란다. 구어체 16/16은 등록 범위 밖이다.
- 구어체 R2의 근거 Q&A 2개는 공식 문체 질문으로 고른 것이어서 실제 서버의 구어체 검색보다 유리하다.
- 이 실행으로 BT25 문항을 미리 보았다. 규칙·문턱·모델은 바꾸지 않았으므로, 한국 공식 BT25 Q&A가 나오면 R1·R2를 그대로 정식 채점한다.

### 2.15.3 성공 기준의 유의점
R1·R2의 기준(n ≥ 10, 정확도 ≥ 97%)은 n이 작으면 약하다. n=10에서 97%를 넘는 결과는 10/10뿐인데, 10/10이어도 Wilson 95% 하한이 72% 수준이고, n=20의 20/20도 83.9%, E55의 16/16도 80.6%이다. 곧 이 기준을 통과해도 실제 정확도가 97% 이상임이 통계적으로 보장되지는 않는다.

그러나 규칙은 사전 등록이므로 결과를 본 뒤 기준을 바꾸지 않는다. 정식 채점에서는 등록된 기준의 성패를 그대로 적고, 맞음/문항 수와 Wilson 95% 구간을 함께 제시해 독자가 기준의 강도를 판단하게 한다. 기준을 강화할 필요가 있으면 기존 항목을 고치지 않고 새 항목으로 더한다.
