## 2. 실험 이력 (시간순)

### E1. 효과 단위 분할 + 요소 태그 (v1)
- 방법: 타이밍 묶음 【】·키워드 《》·〔진화〕·디지크로스·〈룰〉 경계로 분할, 행동 정규식 약 50종, 대상·필터·형식 태그.
- 결과: 효과 단위 8,936개. 「타이밍 × 주 행동」 유형 544개, TF-IDF(글자 2–4gram)+태그 응집 군집(코사인 평균 연결, 거리 0.42) 패턴 1,456개.
- 사용자 검토 결정(7개, 2026-10-17): ① 유형은 행동 중심 ② 다중 행동은 모든 유형에 소속 ③④ 옛/새 문구 10쌍 정규화 ⑤ 행동 6종 룰 조항 연결 보완 ⑥ 결과가 다르면 다른 패턴 ⑦ 미연결 Q&A 2단계 연결.

### E2. Q&A → 효과 단위 연결
- 질문의 【타이밍】·키워드 표기 + 글자 2-gram 유사도로 해당 카드의 효과에 배정. 표본 10/10 정확.
- 5,308 중 4,026 효과 단위 연결(인용구·항목명 2차 연결 333 포함), 1,068은 「일반 판정」으로 가장 가까운 룰 조항에 연결(표본 약 6/10 — 자동 추정 표시).

### E3. LLM 비교 시험 (100문항, 네/아니요 50:50, 정답 Q&A·재진술은 근거에서 제외, Claude=하위 에이전트·웹 금지)
| 방식 | 정답 |
|---|---|
| S1 분류 엔진 단독(근접 Q&A 가중 투표) | 70 |
| S2 Claude 단독(카드 텍스트+질문) | 82 |
| S3 Claude + 글자 2-gram 검색 근거 | **98** |
| S4 Claude + 분류 엔진 근거 | 95 |
- 해석: 근거 제공이 오답을 18%→2~5%로 줄임. S3−S4 차이 3문항은 모두 「다른 카드의 같은 질문」이 S4 근거에서 밀린 경우. 표본 100으로 유의하지 않음.
- Claude 단독은 확신 ≥0.8에서 24/27, <0.8에서 58/73 — 확신도와 정답이 연관.

### E4. LLM 없는 네/아니요 예측 (4,052문항 그룹 5-fold CV; 같은 카드 유사>0.55·전체 유사>0.92 = 같은 그룹)
| 신호 | 정확도 |
|---|---|

| 질문 유사 kNN(패턴·유형·카드 가중, 부정 질문 뒤집기) | 77.4% |

### E5. 질문 규격화
- 질문 형태(가능 여부 33%·유발 여부 22%·정의 6%·결과 6%·순서 3% …)만 맞추면 75.6→75.0%(무효).
- 상황 슬롯(영역·사건·주체·방식·타이밍·부정) 일치 우선 시 75.9→77.8%, 확신 상위 50% 87→90%.
- 양식 시뮬레이션(묻는 것+상황 슬롯 완전 일치 선례): A 같은 패턴 14.0% 커버 96.1% / +B 같은 유형 8.3% 88.7% / +C 효과 무관 18.8% 91.2% → 누적 41.1% 커버 92.4%. (첫 계산에서 자기 자신을 선례로 잡는 버그로 99% 나왔다가 수정.)
- 하이브리드(100문항): 선례 A~C면 엔진 → 94/100(Claude 51회), A+만장일치만 엔진 → 98/100(Claude 85회).

  - 필터는 대상을 좁히는 조건만: 「~마다」「~당」「합계가 ~되도록」로 세거나 비교하는 기준, 조건절(「…하지 않았을 때,」)·출처(「상대의 디지몬의 효과를 받지 않는다」)가 대상·편·필터로 들어가지 않게 했습니다. 「가장 Lv.이 낮은」, 「액티브 상태」, 《키워드》 보유·미보유 필터를 추가했습니다.
  - 행동 이름: 「《S 어택 -1》을 주고」가 키워드 실행으로 잡히던 것, 「선택할 수 있는 Lv. 상한」이 선택·임의로 잡히던 것, 수식 구절(「이 효과로 진화한 …」「…진화할 때」)의 동사가 행동으로 잡히던 것, 「뒤집어서 놓는다」가 시큐리티 공개로 잡히던 것을 고쳤고, 오픈·어플 합체·시큐리티로 되돌림·진화원 아래 놓기(사이 단어 있는 문장) 행동을 추가했습니다. 《리커버리 +1 《덱》》의 《덱》은 매개변수라 행동에서 뺐습니다.
  - 한 단계에 묶이던 것 분리: 「…할 수 없고, ~발휘하지 않는다」「…할 수 있고, DP+2000」「…없으며, 소멸한다」, 「오픈하고, 그중 1장을 …」.
  - 메모리·드로우·코스트 증감 단계는 대상·편·필터를 갖지 않습니다. 선택지 문장(「이하의 효과에서 1개를 발휘한다 ・A ・B」)에는 단계마다 `선택지: 택1`을 붙였습니다(새 키). 「…있을 경우」를 처리 조건으로, `<룰>` 문구를 효과에서 떼어 `룰 문구`로, 《어플 합체》 진화 조건 뒤에 붙은 효과(20개)를 효과로 분석합니다.

## E31. 구어체 질문 → 공식 Q&A 연결: 질문 정규화와 검색 평가 (2026-10-20)

  - 질문 틀 분해 `frame()`: 대상 카드 / 타이밍·키워드 / 상황(기존 `form.slots`) / 묻는 것(발휘·유발·진화·등장·획득·순서·정의·처리·가능).
  - 사전에 없는 토큰 목록: `paper/results/e31_unresolved_terms.json`(고유명칭이 아닌 구어 어미가 대부분이고, 「메페」「카든」 같은 약칭은 사용자 확인 전까지 매핑하지 않음).
- **평가(q_eval_retrieval.py):** 검색 대상은 BT22 이전 공식 Q&A + 같은 카드의 Q&A. 정답은 이유 묶음이 같고 답의 방향이 같은 Q&A(또는 문장이 똑같은 Q&A).
  - **A(원문 포함):** 원문 Q&A도 검색 대상. 사용자가 이미 있는 질문을 다르게 물었을 때.
  - **B(원문 제외):** 원문을 대상에서 빼고 같은 이유 묶음만 정답으로. 처음 보는 질문을 선례에 잇는 일반화 시험(정답이 있는 101문항).
  - 방식: (a) 원문 그대로 2-gram(지금), (b) 질문과 말뭉치 양쪽을 정규화하고 군말·끝맺음을 뺀 2-gram, (c) b + 틀 일치 가산점(묻는 것 +0.08, 상황 +0.10).

| 평가 세트 200 | 방식 | recall@1 | @3 | @10 |
|---|---|---|---|---|
| A 원문 포함 (n=200) | a 지금 | 0.855 | 0.935 | 0.955 |
| | b 정규화 | 0.865 | 0.925 | 0.965 |
| | c 정규화+틀 | 0.875 | 0.915 | 0.950 |
| | 상한(공식 문장 입력, a) | 1.000 | 1.000 | 1.000 |
| B 원문 제외 (n=101) | a 지금 | 0.703 | 0.832 | 0.901 |
| | b 정규화 | 0.713 | 0.842 | 0.911 |
| | c 정규화+틀 | 0.743 | 0.822 | 0.901 |
| | 상한(공식 문장 입력, a) | 0.851 | 0.960 | 1.000 |
| | 상한(공식 문장 입력, c) | 0.861 | 0.941 | 1.000 |
| B 중 원문과 겹침이 적은 문항(정답 Jaccard<0.3, n=83) | a / b / c | 0.711 / 0.735 / 0.759 | 0.819 / 0.831 / 0.807 | 0.904 / 0.916 / 0.904 |

  - 개발 세트(120문항)에서는 A@1 a 0.892 · b 0.850 · c 0.850, B@1 a 0.863 · b 0.836 · c 0.836으로 **정규화가 오히려 약간 낮았습니다**. 평가 세트에서의 +1~4%p는 101~200문항 규모에서 오차 범위(±4%p 안팎)입니다. 그래서 「정규화가 낫다」고 결론내지 않습니다.
  - 상한이 B에서도 0.85에 그치는 것은 이 정답 정의(이유 묶음+같은 방향)가 공식 문장끼리도 한 번에 못 찾을 만큼 엄격하기 때문입니다.
  - 시행착오: (1) 질문만 정규화하고 말뭉치는 원문으로 두면 개발 세트 B@1이 0.863→0.712로 떨어졌고, 양쪽을 정규화하면 0.767이었습니다. (2) 끝맺음을 「~나요?」로 붙이기만 하면 흔한 2-gram이 늘어 점수가 낮아져서, 끝맺음·「이 카드의」를 비교 본문에서 빼는 `content()`를 넣었습니다(0.767→0.836). (3) 카드 일치 가산점은 A에서는 올리지만 B에서는 다른 카드의 같은 이유 묶음을 밀어내서 0으로 했습니다. (4) IDF 가중 2-gram(d)은 이득이 없어 제외했습니다.
- **해석:** 이 시험의 구어체는 원문 어휘를 많이 남겨서 원문 2-gram만으로도 상당히 맞습니다(@10 0.90~0.96). 사전과 틀은 그 위에서 이득이 오차 범위입니다. 사용자 사례처럼 **어휘가 안 겹치고 의미로 이어야 하는 문항**은 사전으로는 한계가 있어, 의미 검색(대조학습 bi-encoder)이 필요합니다. 그 준비물이 `train/train_retriever.py`입니다.
- **브라우저 이식:** `v3_qnorm.js`(전역 `QN`, 84KB, 외부 라이브러리 없음). `qnorm.py`와 구어체 200문항에서 출력·틀이 모두 같음을 확인했습니다. 연결 방법은 `docs/qnorm_integration.md`(판정 도우미 코드는 수정하지 않음).
- **검색 모델 준비(실행 안 함):** `train/train_retriever.py` — 긍정 쌍(이유 묶음 같음+답 방향 같음, 또는 묻는 것·상황·방향이 같고 답이 비슷함), 어려운 부정(문장이 비슷한데 답이 반대), 구어체 증강(평가 세트 문항은 제외, 최신 팩은 학습에서 전부 제외), 평가는 시간 분할과 구어체 세트를 브라우저 2-gram과 같은 질문·같은 말뭉치에서 비교. CPU `--tiny` 스모크 통과(영어 소형 모델이라 수치는 의미 없음). 계획은 `train/README.md` 6절.
- **한계:** 구어체가 LLM이 원문을 바꿔 쓴 것이라 실제 사용자 말투와 다를 수 있고, 6가지 말투가 같은 에이전트 4개에서 나왔습니다. B의 정답은 기존 이유 묶음(자동 군집)에 의존합니다. 평가 문항 수가 적어 방식 간 차이 대부분이 오차 범위입니다.
- 파일: `qnorm.py`, `qnorm_dict.json`, `qnorm_names.json`, `qnorm_vocab.json`, `qnorm_make_dict.py`, `qnorm_make_js.py`, `v3_qnorm.js`, `q_eval_retrieval.py`, `paper/results/colloquial_{test,dev}.json`, `e31_retrieval_{eval,dev}.json`, `e31_*_log.txt`, `colloq_work/`, `train/train_retriever.py`, `docs/qnorm_integration.md`.

### E31 추가: 검색 모델 GPU 학습 결과 (2026-10-21)
- 설정: jhgan/ko-sroberta-multitask, 3 에폭, bs 16, lr 2e-5, 학습 3중쌍 5,981개(GTX 1660 SUPER, 약 30분). 평가 세트와 최신 팩 Q&A는 학습에서 제외. 자세한 내용은 `train/RESULTS_retriever.md`.
- **구어체(n=87, 원문 제외) recall@1/@3/@10:** 브라우저 2-gram 0.713/0.874/0.931 → 학습 전 0.609/0.701/0.713 → **학습 후 0.828/0.897/0.954**. 정규화(`--norm`)를 더하면 0.828/0.908/0.966으로 사실상 같습니다.
- **최신 팩 공식 질문(n=314, 시간 분할):** 2-gram 0.873/0.959/0.990, 학습 후 0.895/0.933/0.990, 정규화 학습 0.857/0.908/0.994. @1은 학습 후가 낫고 @3은 2-gram이 높습니다.
- **해석:** 의미 검색은 구어체에서 @1을 +11.5%p(약 10문항) 올렸습니다. 사전 정규화는 모델에는 이득이 없고(최신 팩 @1은 −3.8%p) 기본 설정을 씁니다. 두 방법이 서로 다른 문항을 맞힐 수 있어, 2-gram과 모델 점수를 합치는(@3 보완) 실험이 다음 단계 후보입니다.
- **유의:** n=87이라 오차가 큽니다(±8%p 안팎). 평가 대상 문항이 87개인 것은 학습 풀에서 평가 문항을 빼서 정답 묶음이 말뭉치에 남은 문항만 세기 때문이며, 앞의 사전 평가(n=101)와는 말뭉치 정의가 달라 수치를 직접 비교하면 안 됩니다.

## E33. 검색 모델을 브라우저용으로 증류 — 준비 (2026-10-21)
- **배경:** E31의 GPU 검색 모델(ko-sroberta 미세조정)은 구어체 recall@1을 0.713에서 0.828로 올렸습니다(n=87). 하지만 110M 파라미터라 아티팩트에서 직접 돌릴 수 없습니다.
- **학생 모델(train/distill_student.py):**
  - 구조: 문자 2·3-gram FNV-1a 해시(32,768칸) → 256차원 임베딩 평균 → 선형층(256→768) → L2 정규화.
  - 손실: 교사 벡터와의 (1−cos) + 배치 내 InfoNCE(구어체 변형 ↔ 원문 교사 벡터).
  - 학습 문장: 이전 팩 질문과 그 구어체 변형 8개씩. 평가 세트와 최신 팩은 뺐습니다.
  - Q&A 쪽은 교사 벡터를 int8로 미리 계산해 둡니다(비대칭 검색).
- **브라우저 이식(v3_qemb.js):** 순수 JS로 해시·int8 역양자화·행렬곱을 합니다.
  - 작은 모델로 내보낸 결과에서 Python과 코사인 1.00000이 나왔습니다(tests/tqemb.js). 질문 하나 검색에 5ms(작은 모델 기준)입니다.
  - TextEncoder 없이도 동작합니다.
- **판정 도우미 연결:** 질문 추천에 「의미가 비슷한 공식 질문」을 더하고, 근거에 「의미 검색」 탭을 추가했습니다.
  - **판정 경로에는 넣지 않았습니다.** 정확도를 따로 재기 전까지는 근거와 추천으로만 씁니다.
  - 모델 파일이 없으면 이 기능은 꺼집니다(tests/tsem.js). 기존 시험(tcr·tdist·tac)도 통과했습니다.
- **다음:** GPU에서 교사로 증류하고(시간 분할 평가 + 전체로 다시 학습해 내보내기), 승인 기준을 넘으면 qemb 파일을 함께 배포합니다.
  - 승인 기준: 학생의 구어체 recall@3이 교사의 95% 이상, 파일 15MB 이하.

## E34. 판정 도우미 서버(이 PC) — 서버 방식으로 전환 (2026-10-21)
- **결정(사용자):** 검색 모델은 브라우저에 넣지 않고 서버에서 돌립니다. 첫 서버는 이 PC입니다.
- **server/app.py(FastAPI):** 페이지와 API를 같은 서버에서 냅니다. 아티팩트는 외부 서버를 부를 수 없을 가능성이 높아서 이렇게 했습니다.
  - `GET /`: 판정 도우미(`build_v3.py --server` → server/static/index.html. 배포판과 같고 AI 판정은 없습니다).
  - `POST /api/search`: 검색 모델로 공식 Q&A 인덱스를 돌려줍니다. 판정은 하지 않습니다. Q&A 벡터는 미리 계산해 캐시합니다.
  - `/api/rulings`: 확인 판정. 읽기는 누구나, 쓰기는 심판 키(server/judges.json, git 제외)가 있어야 합니다.
  - `/api/reports`: 이용자 제보. 누구나 보낼 수 있고, IP당 5초 간격 제한이 있습니다. 심판이 「받은 제보 불러오기」로 검토해 확인 판정으로 저장합니다.
  - 저장소는 SQLite(server/judge.db)입니다.
- **페이지 연결(v3_ui.js):** 서버 모드(`window.__SERVER_API`)에서는 아티팩트 db 대신 서버 API를 같은 방식으로 씁니다.
  - 확인 판정 목록은 20초마다 갱신합니다.
  - 심판 로그인은 키를 브라우저 localStorage에 저장합니다.
  - 제보는 코드 복사 없이 바로 서버로 보냅니다.
  - 의미 검색은 서버 API를 비동기로 불러 질문 추천과 「의미 검색」 탭에 씁니다.
  - 아티팩트 빌드(test·dist)는 그대로 동작합니다(tcr·tdist·tac·tsem 통과).
- **확인:** 이 PC에서 띄워 브라우저로 열었습니다. 페이지, 판정 보류, 제보 칸, 확인 판정 탭이 정상이고 API 시험(제보, 키 확인, 판정 저장, 키 없는 접근 403)을 통과했습니다.
