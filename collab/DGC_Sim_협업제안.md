# DGC Sim × 카드 효과 판정 도우미 협업 제안

## 왜 협업하나

판정 도우미는 카드 문구와 공식 Q&A를 비교해서 판정합니다. 최신 팩 공식 Q&A로 시험하면(이전 팩만 보고 판정), 네/아니요 질문의 48%를 정확도 99%로 Claude 없이 답합니다.

나머지 질문은 문구 비교만으로는 답이 나오지 않습니다. 그 카드만의 사실을 묻거나, 여러 카드가 얽힌 상황을 묻기 때문입니다. 카드 효과를 실제로 실행해 보는 **룰 엔진**이 있어야 답할 수 있습니다. DGC Sim이 바로 그 엔진입니다.

## 서로 주고받을 것

| 판정 도우미 쪽이 드릴 것 | DGC Sim 쪽에 부탁드릴 것 |
|---|---|
| 한글 카드 약 8,900개 효과의 룰북 구조 분해 (발동 시점·조건·대상·처리 단계, 종합 룰 조항 번호) | 시범 문항의 상황을 엔진에서 재현해 본 판정 결과 |
| 공식 Q&A 5,308개와 카드·효과 연결 데이터 | 구현이 안 된 카드나 효과의 목록 (어디까지 커버하는지) |
| 엔진 판정과 공식 답이 어긋난 문항 목록 → 카드 구현 버그를 찾는 테스트 케이스로 활용 | (가능하면) 상황을 넣으면 결과를 돌려주는 호출 방법 |
| 검수 정답셋과 평가 스크립트 (Wilson CI·McNemar) | |

모든 데이터와 코드는 이미 공개 저장소에 있습니다: https://github.com/Marhnie/digimon-card-effects

## 1단계: 시범 (1~2주)

- **문항:** `collab/pilot_set.csv`의 309개. 최신 팩 네/아니요 Q&A 가운데 지금 엔진이 확신하지 못한 문항 전부입니다.
  - 단일 카드: 이유 있음 117 / 이유 없음 116
  - 다른 카드가 얽힘: 이유 있음 37 / 이유 없음 39
- **방법:** `question` 칸만 보고 엔진으로 상황을 재현합니다. 결과를 `sim_answer`(네/아니요/재현 불가)에, 필요하면 메모를 `sim_note`에 적어 주시면 됩니다. 공식 답(`gold`)은 나중에 대조합니다.
- **일부만 해도 됩니다.** 예를 들어 무작위 50문항이면 커버율과 정확도를 대략 추정할 수 있습니다.
- **판정 도우미 쪽에서 볼 것:** 재현할 수 있는 비율, 공식 답과의 일치율, 그리고 엔진 판정과 합쳤을 때 Claude 없이 답하는 비율이 얼마로 오르는지.

## 엔진을 믿을 수 있는지 먼저 확인

DGC Sim도 사람이 구현한 엔진이라 틀린 카드가 있을 수 있습니다. 그래서 바로 연동하지 않고, 공식 답이 있는 문항으로 먼저 채점합니다.

- **채점 기준:** 시범 문항 309개는 모두 공식 답이 있습니다. 재현한 문항 중 공식 답과 맞는 비율이 **95% 이상**이어야 연동합니다. 판정 도우미 엔진과 같은 기준입니다.
- **팩·효과 종류별로 따로 봅니다.** 전체 정확도가 높아도 특정 팩이나 효과 유형에서 자주 틀리면, 그 부분은 엔진 판정을 쓰지 않습니다.
- **연동 후에도 단독 판정은 하지 않습니다.**
  - 판정 도우미 엔진과 DGC Sim의 답이 같으면 Claude 없이 답합니다.
  - 둘이 다르면 Claude나 사람이 판정하고, 확정된 답은 선례로 저장합니다.
  - DGC Sim 쪽 카드 구현이 틀린 것으로 보이면 그 카드를 제작자에게 알려 드립니다.
- **새 팩이 나오면 다시 채점합니다.** 공식 Q&A가 공개될 때마다 같은 방식으로 정확도를 다시 확인합니다.

## 2단계: 연동 (시범 결과가 좋으면)

질문 하나를 아래 형식으로 엔진에 넘기고, 엔진은 결과를 돌려줍니다.

```json
{
  "cards": ["BT24-001", "EX10-058"],
  "board": {"me": {"battle": ["BT24-001"], "trash": ["EX10-058"]}, "opp": {}},
  "action": {"type": "effect", "card": "BT24-001", "effect": "【진화 시】"},
  "ask": "EX10-058의 효과를 발휘할 수 있는가"
}
```

```json
{"answer": "아니요", "trace": ["…엔진 로그…"], "covered": true}
```

- 질문 문장을 이 형식으로 바꾸는 일은 판정 도우미 쪽(카드 연결·룰북 구조)이 맡습니다.
- 엔진을 공개하기 어렵다면 일괄 처리 방식도 괜찮습니다. 문항 파일을 드리면 결과 파일을 돌려주시는 방식입니다.
- 엔진 판정으로 답한 경우, 화면에 「DGC Sim 판정」으로 출처를 표시합니다.

## 출처와 공개 범위

- 논문이나 공개 페이지에는 DGC Sim과 제작자를 원하시는 방식으로 표기합니다. 익명 표기도 가능합니다.
- 엔진 코드나 카드 구현은 받지 않습니다. 판정 결과만 받습니다.
- 받은 판정 결과를 공개 저장소에 올려도 되는지는 따로 여쭙겠습니다.
